Insert syntax: one document at a time

The pattern is collection.insert_one(document).

  • collection identifies where the document goes: our variable is demo.
  • document is a Python dictionary of field–value pairs.
  • insert_one() adds that one document to MongoDB.

Our first practice document will be:

{"_id": 1, "name": "Alice", "likes": 2}

The _id values 1, 2, and 3 let us select a specific practice record in the next steps.

Reference: PyMongo — insert documents

Update one document: change a value

The pattern is collection.update_one(filter, update).

demo.update_one(
    {"_id": 1},
    {"$set": {"likes": 7}}
)

print(demo.find_one({"_id": 1}))
Part Meaning
{"_id": 1} Select Alice's document.
{"$set": {"likes": 7}} Change its likes value from 2 to 7.

Reference: PyMongo — update documents

Update one document: add a new field

Use the same $set syntax for a field that does not exist yet.

demo.update_one(
    {"_id": 2},
    {"$set": {"topic": "data"}}
)

print(demo.find_one({"_id": 2}))

Ben's document now includes "topic": "data". Its name and likes remain in the document.

A new field was added to the existing document. The collection still has three documents. This is how we can store an additional analysis field later.

Reference: MongoDB — $set changes or adds a field

Example 1: a complete document query

Paste your complete Python export. This test ranks tweet documents by their stored like count.

filter = {}
project = {'tweet.id': 1, 'tweet.text': 1,
           'tweet.public_metrics.like_count': 1,
           'user.username': 1, 'tweet.created_at': 1}
sort = list({'tweet.public_metrics.like_count': -1}.items())
limit = 10
maxTimeMS = 60000
result = client['lab8']['tweet_collection'].find(
    filter=filter, projection=project, sort=sort,
    limit=limit, max_time_ms=maxTimeMS
)

Use the same three lines after every query

After running the complete find() or aggregate() query, use:

records = list(result)
df = pd.json_normalize(records)
display(df)

1 · Read. list(result) reads the returned documents into a Python list.

2 · Normalize. pd.json_normalize(records) creates a DataFrame from the returned fields.

3 · Display. display(df) shows the full table before any field selection or formatting.

No hardcoded columns here. Do not rename, reindex, or require tweet/hashtag fields just to load a result. Write display(df), not df.display().

References: Read cursor results · pandas json_normalize

One conversion works for different result shapes

The conversion is the same. The column names are allowed to change when the query changes.

Returned record shapeExample DataFrame columns
Nested tweet documenttweet.text
tweet.public_metrics.like_count
Projected user rankingusername, followers_count
Count pipelinetweet_count or user_count
Hashtag aggregationWhatever the pipeline returns, such as _id and count

Works for flat and nested document records. A list inside a field is not automatically expanded into one row per item. The three-line block expects a document cursor, not a scalar returned by count_documents().

display(df) preserves the DataFrame table display. In Colab, use the table icon to switch to interactive exploration.

Sorting and filtering in the viewer help you inspect the result. They do not rerun MongoDB or replace the submitted analysis.

To prefer interactive tables throughout this Colab notebook, you may optionally enable:

from google.colab import data_table
data_table.enable_dataframe_formatter()

Optional display setting; the existing MongoDB connection does not change. Colab supplies the interaction—display(df) alone does not guarantee the same controls in GitHub or another notebook viewer.

Reference: Google Colab: interactive DataFrames

Avoid stale data and misleading fallbacks

Current query→Three-line conversion→Table / chart

A cursor is consumed. After list(result), rerun the query before rerunning the conversion. To redisplay existing data, run only display(df).

df is reused. A later query replaces its contents. Before asking Gemini to format or plot, inspect the current table and:

df.columns.tolist()

An empty table can be a valid query result—but first rule out an exhausted cursor, the wrong database/collection, or a failed/unrun query. Do not hide query errors or silently substitute an old DataFrame.
