Part 1 · Understand the record

A small social-post document

{
    "_id": "w10-p001",
    "text": "Post 001: practicing AI with Python.",
    "likes": 17,
    "user": {
        "id": "u01", "name": "Avery",
        "followers": 120,
        "location": {"city": "Fairfax", "state": "VA"},
        "interests": ["learning", "ai"]
    },
    "entities": {
        "hashtags": [{"tag": "AI"}],
        "mentions": [{"username": "u02"}]
    }
}

Read the field paths

text: a string.
likes: a number.

user.location.city: a field inside nested objects.

user.interests: an array of strings.

entities.hashtags and entities.mentions: arrays of objects.

Each record is one post, not one user. A user appears in several posts.

Part 1 · Build the same data · Cell B

Generate 100 simple documents

Run after Cell A. This builds a Python list; it does not write to MongoDB yet.

documents = []
for i in range(1, 101):
    u = (i - 1) % 10
    topic = topics[u]
    tags = [{"tag": topic}]
    if i % 2 == 0:
        tags.append({"tag": "Learning"})
    documents.append({
        "_id": f"w10-p{i:03d}",
        "text": f"Post {i:03d}: practicing {topic} with Python.",
        "likes": (i * 17) % 101,
        "user": {
            "id": f"u{u + 1:02d}", "name": names[u],
            "followers": followers[u] + 10 * ((i - 1) // 10),
            "location": {"city": cities[u % 5], "state": "VA"},
            "interests": ["learning", topic.lower()]
        },
        "entities": {
            "hashtags": tags,
            "mentions": [] if i % 5 == 0 else [
                {"username": f"u{(u + 1) % 10 + 1:02d}"}]
        }
    })
print(len(documents), documents[0]["_id"])

Expected: 100 w10-p001. Every record has a unique fixed ID.

Part 1 · Update an existing value

Filter chooses the record; $set chooses the changes

The pattern is collection.update_one(filter, update_document).

changed = demo.update_one(
    {"_id": "w10-demo"},
    {"$set": {"likes": 999, "user.location.city": "Test City"}}
)
print("Matched:", changed.matched_count, "Modified:", changed.modified_count)
print(demo.find_one({"_id": "w10-demo"}))
PartMeaning
{"_id": "w10-demo"}Match exactly the temporary document.
"$set"Assign the specified field values; keep other fields.
"user.location.city"Change only the city; keep state: "VA".

First run: matched 1, modified 1. Repeating the same values can report modified 0; that is not a connection failure. Avoid an empty filter for this update.

Reference: PyMongo — update documents

Part 1 · Add new fields

$set can add a scalar field and a list

changed = demo.update_one(
    {"_id": "w10-demo"},
    {"$set": {
        "reviewed": True,
        "labels": ["lecture", "practice"]
    }}
)
print(demo.find_one({"_id": "w10-demo"}))

New scalar field

reviewed did not exist. It now stores a Boolean value.

New array field

labels did not exist. It now stores a list of two strings.

If a field already exists, $set replaces that field's value. Setting labels again replaces the whole list; it does not append an item.

Reference: MongoDB — $set

Part 1 · Update an array

Add an item without replacing the list

demo.update_one(
    {"_id": "w10-demo"},
    {"$addToSet": {"labels": "checked"}}
)
print(demo.find_one({"_id": "w10-demo"})["labels"])

Expected: ["lecture", "practice", "checked"].

OperationEffect on a list
$setAssign or replace the entire field value.
$pushAppend an item; repeated runs can append duplicates.
$addToSetAdd the item only when it is not already present.

Run the shown update twice. The string checked should still appear once. This is not a general command for removing older duplicates.

Reference: MongoDB — $addToSet

Part 2 · The only conversion pattern

Read → normalize → display

Immediately after running a complete query, use this pattern:

records = list(result)
df_posts = pd.json_normalize(records)
display(df_posts)
LineWhat it does
list(result)Read the returned document cursor into a Python list.
pd.json_normalize(records)Build columns from the fields actually returned.
display(df_posts)Show the DataFrame before selecting or renaming columns.

For the next exercises, change only the DataFrame name to df_users and df_tags. Write display(df), not df.display().

This pattern accepts document cursors from find() or aggregate(), not scalar counts or write-operation result objects. Normalizing nested dictionaries does not automatically turn each array item into a row.

Reference: pandas — json_normalize

Exercise 2 · MongoDB AI

Rank distinct users, not repeated post records

In Aggregations, ask MongoDB's built-in AI:

In lec9.dummy_data, group posts by user.id so each user appears once. Return user_id, name, and that user's maximum stored user.followers as followers_count. Sort followers_count descending, then user_id ascending. Return the top 5 users. Do not sum the follower counts.

Run, check, and export Python with Include Driver Syntax.

Reference aggregation for checking your export
result = client["lec9"]["dummy_data"].aggregate([
    {"$group": {
        "_id": "$user.id", "name": {"$first": "$user.name"},
        "followers_count": {"$max": "$user.followers"}
    }},
    {"$sort": {"followers_count": -1, "_id": 1}},
    {"$limit": 5},
    {"$project": {"_id": 0, "user_id": "$_id",
                  "name": 1, "followers_count": 1}}
])

Names are constant for each user in this teaching dataset. $max chooses the largest stored snapshot, not necessarily a live or latest count.

Exercise 3 · MongoDB AI · Nested array

Count hashtag items inside the arrays

In lec9.dummy_data, unwind entities.hashtags and count occurrences of each entities.hashtags.tag. Return tag and occurrences, preserve capitalization, and sort occurrences descending then tag ascending. Return up to 10 tags. Do not unwind mentions or user.interests, and do not extract tags from text.

A post with two hashtags contributes two occurrences. Unwinding an unrelated array too can multiply rows and overcount.

Reference aggregation for checking your export
result = client["lec9"]["dummy_data"].aggregate([
    {"$unwind": "$entities.hashtags"},
    {"$group": {"_id": "$entities.hashtags.tag",
                "occurrences": {"$sum": 1}}},
    {"$sort": {"occurrences": -1, "_id": 1}},
    {"$limit": 10},
    {"$project": {"_id": 0, "tag": "$_id", "occurrences": 1}}
])

Reference: MongoDB — $unwind
