One insert method; a simple for loop

Part 1 · First update

Update 1: change an existing field

The syntax is collection.update_one(filter, update).

demo.update_one(
    {"_id": 20},
    {"$set": {"likes": 30}}
)
print(demo.find_one({"_id": 20}))
PartMeaning
{"_id": 20}Choose the one document with ID 20.
$setAssign a value without replacing the whole document.
"likes": 30Change the existing likes field from 5 to 30.

The post now has 30 likes. The collection still contains 20 documents.

Before: likes: 5→After: likes: 30
Instructor screenshots
Part 1 · Second update

Update 2: add a new field

Use the same method and the same $set operator. This time, the key does not exist yet.

demo.update_one(
    {"_id": 20},
    {"$set": {"labels": ["lecture", "practice"]}}
)
print(demo.find_one({"_id": 20}))

labels is the new key; ["lecture", "practice"] is its list value.

Existing key → change its value.
New key → add the key and its value.

All other fields stay in place. This example assigns a whole list; it is not an append operation.

Reference: MongoDB $set

Before: no labels field→After: labels: ["lecture", "practice"]

Part 2 · The only conversion pattern

Read → normalize → display

Immediately after running a complete query, use this pattern:

records = list(result)
df_posts = pd.json_normalize(records)
display(df_posts)
LineWhat it does
list(result)Read the returned document cursor into a Python list.
pd.json_normalize(records)Build columns from the fields actually returned.
display(df_posts)Show the DataFrame before selecting or renaming columns.

For the next exercises, change only the DataFrame name to df_users and df_tags. Write display(df), not df.display().

This pattern accepts document cursors from find() or aggregate(), not scalar counts or write-operation result objects. Normalizing nested dictionaries does not automatically turn each array item into a row.

Reference: pandas — json_normalize

Exercise 2 · MongoDB AI

Find the most-followed users

In Aggregations, try this MongoDB AI prompt:

Which users have the most followers?

Check the answer: each user should appear once, not once per post. Followers should not be summed across that user's posts.

Reference aggregation / backup query
result = client["lec9"]["dummy_data"].aggregate([
    {"$group": {
        "_id": "$user.name",
        "followers": {"$max": "$user.followers"}
    }},
    {"$sort": {"followers": -1}}
])

In this example, $group produces a row for each fictional user and $max reads the follower count. Check the query before exporting it.

Run the query, inspect it, and export complete Python with Include Driver Syntax.

Exercise 3 · MongoDB AI

Count the hashtags inside the arrays

In Aggregations, try this MongoDB AI prompt:

Which hashtags are used most often?

Check the stages: $unwind opens the hashtag array; $group counts tag values; $sort orders the counts.

Reference aggregation / backup query
result = client["lec9"]["dummy_data"].aggregate([
    {"$unwind": "$entities.hashtags"},
    {"$group": {"_id": "$entities.hashtags.tag",
                "occurrences": {"$sum": 1}}},
    {"$sort": {"occurrences": -1, "_id": 1}}
])

A post with two tags contributes two occurrences. Do not unwind the unrelated interests array too, or you can multiply the counts. Preserve tag capitalization.
