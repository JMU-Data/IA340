Another option: keep people and cities separate

People · 3 documents

{"_id":"P1", "name":"James", "city_id":"C1"}
{"_id":"P2", "name":"David", "city_id":"C2"}
{"_id":"P3", "name":"Thomas", "city_id":"C1"}

Cities · 2 documents

{"_id":"C1", "name":"Chicago"}
{"_id":"C2", "name":"New York"}

Embedding: put the city details inside each person (previous slide).

Referencing: store only a city_id in the person, then find the matching city when needed.

Why choose it? Chicago is stored only once, so changing its name is easy. But showing a person's city takes an extra query or a join-like $lookup.

Both ways work in MongoDB. We use embedding when related details are usually read together. MongoDB: Embedding vs References

When is a schema defined?

Relational: schema on write

Design tables + relationships
↓
Declare columns, types, constraints
↓
Insert rows that match the schema

MongoDB: schema on read (flexible by default)

Insert typed documents, even if optional fields differ
↓
Store and retrieve a mix of field shapes
↓
Queries/apps interpret expected fields

Important qualification: “schema on read” describes a flexible way to use MongoDB. BSON fields still have types, and MongoDB can enforce schema validation during writes.

Design first when useful; flexible does not mean unstructured or automatically valid.

JSON vs. BSON: readable documents, typed storage

MongoDB documents look like JSON when we read them, but MongoDB stores them internally in BSON (binary JSON).

JSON / JSON-like view

{ "name": "James", "city": "Chicago", "age": 32 }

Easy for people and APIs to read. Fields and values look like familiar JSON.

BSON in MongoDB

name: Stringcity: Stringage: Number

MongoDB's binary storage format. It also supports types such as Date and ObjectId.

Example: "joined": "2024-01-01" is a string. Store a Python datetime instead and MongoDB uses a BSON Date, which supports date queries.

The driver handles the conversion. BSON is not a different database you must create. BSON Types · PyMongo Dates

IA 340 · Wednesday51 / 61

Cell 8 · insert tweets into MongoDB

users_by_id = {str(user.id): user.data
               for user in (tweets.includes or {}).get("users", [])}
collected_at = datetime.now(timezone.utc).isoformat()

for tweet in (tweets.data or []):
    tweet_json = {}
    tweet_json["tweet"] = tweet.data
    tweet_json["user"] = users_by_id.get(str(tweet.author_id))
    tweet_json["collection_meta"] = {"source": "x_api", "query": query,
                                     "retrieved_at": collected_at}
    try:
        tweet_collection.insert_one(tweet_json)
        print(tweet_json["tweet"].get("created_at"))
    except DuplicateKeyError:
        pass

Each post is stored with the matching author and collection time. A repeated tweet ID will not create a duplicate document.

FINAL PROJECT · Collect up to 500 posts across pages

FINAL PROJECT EXAMPLE — NOT FOR LAB 8. Here, next_token connects multiple API pages. Set your Final Project's own collection (project_collection) and assigned search (project_query) first. Run this example only when Final Project collection is authorized.

# FINAL PROJECT — use the separate project collection and assigned query.
# Set project_collection and project_query during the Final Project.
def collect_project_posts(project_collection, project_query):
    MAX_TWEETS = 500
    MAX_PAGES = 10  # Avoid unlimited paid API requests.
    page_token = None
    project_collection.create_index(
        [("tweet.id", pymongo.ASCENDING)], unique=True
    )

    for page_number in range(MAX_PAGES):
        stored = project_collection.count_documents({})
        if stored >= MAX_TWEETS:
            break

        response = tweet_client.search_recent_tweets(
            query=project_query, max_results=100, next_token=page_token,
            expansions=["author_id"],
            tweet_fields=["created_at", "entities", "lang", "public_metrics", "geo"],
            user_fields=["id", "location", "name", "public_metrics", "username"]
        )
        users_by_id = {str(u.id): u.data
                       for u in (response.includes or {}).get("users", [])}
        collected_at = datetime.now(timezone.utc).isoformat()

        for tweet in (response.data or []):
            if stored >= MAX_TWEETS:
                break
            doc = {
                "tweet": tweet.data,
                "user": users_by_id.get(str(tweet.author_id)),
                "collection_meta": {"source": "x_api", "query": project_query,
                                    "retrieved_at": collected_at}
            }
            try:
                project_collection.insert_one(doc)
                stored += 1
            except DuplicateKeyError:
                pass

        page_token = (response.meta or {}).get("next_token")
        print(f"Page {page_number + 1}: {stored} unique posts stored")
        if not page_token:
            break

    return project_collection.count_documents({})

# Run in the Final Project after project_collection and project_query are set:
collect_project_posts(project_collection, project_query)

Fewer than 500 may be returned if the API has no next page or records are duplicates. Do not use lab8.tweet_collection as the Final Project collection.
