Document Query04 / 29

Querying MongoDB Documents

Each stored document contains an embedded tweet document and an embedded user document. Hashtags are an array inside the tweet.

{
  "tweet": {
    "text": "Learning AI with data",
    "lang": "en",
    "entities": {"hashtags": [{"tag": "AI"}, {"tag": "Data"}]}
  },
  "user": {"name": "Maya", "location": "Richmond"}
}

Use dot notation to reach a nested field: tweet.text, tweet.lang, or user.location.

Document Query05 / 29

MQL Syntax and Quotes

MongoDB's Filter and STAGES editors use JSON-like MongoDB Query Language (MQL).

{"tweet.public_metrics.like_count": {"$gt": 0}}
Part Meaning
"tweet.public_metrics.like_count" The quoted field path. A dot reaches a nested field.
"$gt" and 0 The greater-than operator and a number. Quote operator names, not numbers.
{ }, [ ], :, , A document, an array, a key–value separator, and an entry separator.
"en" A quoted text value.

Quote field names, operator names, and text values. Leave numbers, true, false, and null unquoted.

In the Filter box, enter only the filter document, such as the example above.

Source: MongoDB query syntax

Document Query06 / 29

Document Query Syntax

A filter document describes which records to retrieve. Read the field, the operator, and the value.

Equality

{"tweet.lang": "en"}

Keep a document when tweet.lang equals "en".

Comparison

{"tweet.public_metrics.like_count": {"$gt": 0}}

Keep a document when its like count is greater than 0.

Field"tweet.public_metrics.like_count"

The dotted path reaches a nested value.

Operator"$gt"

The comparison to perform: greater than.

Value0

A number, not the string "0".

$gt is a MongoDB operator. The dollar sign is part of the operator name. Later, in aggregation, a string such as "$user.name" has a different role: it reads a field value.

Source: MongoDB query syntax · Document structure

Common Query Operators

Select an operator and compare the highlighted field with the matching rows.

{"tweet.lang": "en"}

Equality: {"tweet.lang": "en"} is shorthand for {"tweet.lang": {"$eq": "en"}}.

$in uses an array [ ... ] of acceptable values. $exists: true checks that a field is present, even if its value is null.

Document Query08 / 29

$exists: true and $ne: null

These filters test different things. You do not have to add $exists: true before using $ne: null.

Field is present

{"user.location": {"$exists": true}}

Field is present and not null

{"user.location": {"$ne": null}}
Stored location $exists: true $ne: null
Field missing No No
null Yes No
"" (empty string) Yes Yes
"Richmond" Yes Yes

Neither filter excludes an empty string. A document count is not a distinct-user count.

Reference: $exists and non-null values

Document Query09 / 29

Logical Query Operators

$and: both conditions must be true. $or: either condition can be true.

{
  "$and": [
    {"user.location": {"$ne": null}},
    {"user.public_metrics.followers_count": {"$gt": 500000}}
  ]
}

Read the brackets: [ ... ] holds the conditions; each { ... } is one complete condition. A comma separates them. $and needs all conditions; $or needs at least one.

This example tests a non-null location and more than 500,000 followers.

Source: MongoDB logical conditions

Document Query12 / 29

Query Lists and Arrays

Use dot notation to query an item inside an array. Use $size to query the number of items.

{"tweet.entities.hashtags.tag": "AI"}

...hashtags.tag looks inside the hashtag objects. $size: 1 checks the length of the whole array. Both queries return matching tweet documents.

Document Query13 / 29

Query Bar Options

Filter: choose documents. Project: choose fields. Sort: change order. Limit: restrict the number returned.

# Filter (separate Atlas input)
{"tweet.public_metrics.like_count": {"$gt": 0}}
# Project
{"_id": 0, "tweet.text": 1, "tweet.public_metrics.like_count": 1}
# Sort
{"tweet.public_metrics.like_count": -1}
# Limit
2

Project: 1 keeps a field; "_id": 0 hides the identifier. Sort: 1 is ascending and -1 is descending. Limit: 2 keeps the first two results.

Source: Atlas Query Bar

Document Query14 / 29

Exported Query — Keep the Query, Not the Connection

✕ DO NOT COPY — connection setup 
client = MongoClient("YOUR_CONNECTION_STRING")
✓ KEEP — query code 
filter = {'tweet.public_metrics.like_count': {'$gt': 0}}
project = {'_id': 0, 'tweet.text': 1,
           'tweet.public_metrics.like_count': 1}
sort = list({'tweet.public_metrics.like_count': -1}.items())
limit = 2
maxTimeMS = 60000
result = client['lab8']['tweet_collection'].find(
    filter=filter, projection=project,
    sort=sort, limit=limit, max_time_ms=maxTimeMS
)

The client[...] inside result stays. Keep any variables that this query uses with it.

Never put credentials in GitHub code or notebooks: no API keys, connection strings, passwords, certificates, or other authentication details. The excluded line above uses a placeholder, not a real connection.

Aggregation Pipeline16 / 29

Aggregation Pipeline Overview

An aggregation pipeline processes documents through multiple stages. Each stage's output becomes the next stage's input.

Documents→$match→$group→$sort→Results
Stage What it does Stage What it does
$match Filter documents $count Count documents
$project Select or reshape fields $unwind Expand an array
$sort Order results $sortByCount Group, count, and sort
$limit Keep a limited number $group Summarize by a key

Open the Aggregations tab. Add one stage at a time and inspect its output.

Aggregation Pipeline19 / 29

Example: Most Popular Hashtag

Use the stage dropdowns in order: $unwind → $sortByCount → $limit.

[
  {"$unwind": {"path": "$tweet.entities.hashtags"}},
  {"$sortByCount": "$tweet.entities.hashtags.tag"},
  {"$limit": 1}
]

"$tweet.entities.hashtags" reads a field. The $ here marks a field reference, not an operator. Count .tag, not the whole hashtag object. A tie can return any top tag.

Reference: $unwind and array processing

Aggregation Pipeline20 / 29

Example: Top Twitter User by Tweet Count

$group puts documents with the same key together. $sum: 1 counts the documents in each group.

[
  {"$group": {"_id": "$user.name", "user_count": {"$sum": 1}}},
  {"$sort": {"user_count": -1}},
  {"$limit": 1}
]

This example groups by name. Use user.id when you need distinct users. The Atlas screenshots tab below the title shows your $group, $sort, and $limit stages.

Explain Plan in MongoDB Atlas

Explain shows how MongoDB executes a query or pipeline.

Explain

Execution stages, documents/keys examined, results returned, and execution time.

Interpret

AI reads the query and its Explain Plan and describes the logic, performance, and possible improvements.

Look for COLLSCAN (collection scan) or IXSCAN (index scan). A LIMIT stage can stop a scan early.

Explain is not a correctness certificate. A fast query may still answer the wrong question. Next, use Interpret on the generated queries and review its recommendations.

Reference: Explain and Interpret

Regular Expression: What Does i Mean?

In Documents → Filter, the instructor used:

{"tweet.text": {"$regex": "AI", "$options": "i"}}

i means case-insensitive: AI, Ai, and ai match. An unanchored regex can match inside a larger word; it does not mean “the topic AI.”
